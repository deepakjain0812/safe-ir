Research question

Can agent proposals be constrained by observable evidence?

The framework separates proposing a recovery action from authorizing one. The research platform tests whether a policy layer can identify unsupported or potentially destructive proposals without assuming the LLM itself is a safety authority.

01 · OBSERVE

Live incident telemetry

A disposable Orders → Payments → Inventory chain exposes HTTP failures and response latency under controlled fault injection.

02 · DECIDE

Evidence-constrained policy

ECRA can ALLOW, DENY, or REQUIRE_APPROVAL based on the proposal and observed incident conditions.

03 · VERIFY

External measurement

Python experiment runners re-probe actual endpoints after a lab fault reset and record observed recovery behavior, rather than trusting a simulated recovery label.

System design

A proposed action is not an executable command.

SAFE-IR models the decision, executor, and verification boundaries explicitly. The experimental controller cannot run arbitrary host commands, and its action surface is constrained to the disposable lab.

Reproducible experiments

Separate policy decisions from measured recovery.

The project has two experimental tracks. Both are research prototypes, not production safety certification.

v0.1.0 · Synthetic feasibility study

Six predefined incidents explore fixed proposal decisions and simulated outcomes. Repeated seeds do not create independent incidents. The synthetic recovery field is an oracle comparison, not observed restoration.

View synthetic experiments ↗

v0.2.0 · Live service lab

Three Java 21 Spring Boot services, HTTP fault injection, matched proposal replay, real Ollama smoke testing, and external HTTP verification. The supported remediation is a controlled fault reset, not real infrastructure repair.

View live lab and tests ↗

Important negative result: In the first successful model-backed smoke test, Ollama proposed SCALE_UP during an injected Payments HTTP failure. ECRA denied the proposal; the baseline policy permitted it, but the shared restricted executor did not support scaling. Neither arm recovered. This demonstrates a policy-decision difference, not proven safer execution or improved recovery.
